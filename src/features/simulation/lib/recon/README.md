# RECON-SCEN — scenario reconciliation (lib/recon)

## Core rule (fixed)

**Assumed path(day) = Σ_tenor( KRD_tenor@baseDate × cumΔbp_tenor(day) )** vs
the engine's realized valuation path (`decompositionDaily.bondMtm + swapMtm`);
the difference is the **잔차 path** — never "테타", never "carry"
(`scenario-recon.test.ts` guards the name). KRD is held constant at baseDate;
the M3 caption states this linearity assumption on screen, because that gap is
exactly what the 잔차 measures (aging, remaining-tenor drift, FM convexity,
pillar bucketing).

## Modules

- `path-matrix.ts` — M2, the designed day × tenor cumulative-Δbp matrix.
  Single source of truth for BOTH the Results 대사 view and the Configure
  시계열형 multi-series preview. Composed only from existing machinery
  (waypoint lerp, BOK staircase, terminal shock-curve interp); the tenor zone
  stitching cites the backend's chart.py rules it mirrors.
- `scenario-recon.ts` — M1 (KRD grid @ baseDate, two documented sources) and
  M3 (assumed / engine / 잔차 lanes on the run's business-day axis).
- `settlement-lane.ts` — T4b, the swap settlement-cash lanes (projected
  events vs the engine recon's settleCf windows).
- `fixtures.ts` + `__fixtures__/*.json` — REAL `/api/simulate` captures.

## Fixtures

Generated by `scripts/recon-fixtures/generate_fixtures.py` (backend FastAPI
TestClient, in-process — no server). Every market input is explicit in the
payload (irsCurves, fixing fields, fundingRate), so the runs are deterministic
and need no backend `Data/`. Regenerate only against the backend head pinned
in RECON_SCEN_REPORT.md, and expect the pinned residual numbers in
`scenario-recon.test.ts` to move if the engine changes.

| fixture | scenario | what it pins |
|---|---|---|
| `linear.json` | +5bp parallel, near-linear waypoint path | 잔차 ≈ 0 within stated tolerance (≤ max(₩100k, 1.8%·assumed); observed worst ₩566,157 = 1.61%, final day) |
| `shaped.json` | non-monotone path + tenor/credit/IRS spreads | 잔차 = engine-vs-linear gap, final-day value pinned (₩1,909,929) |
| `settlement.json` | zero shock, fixings already known | valuation lanes exactly 0; projected settlements == realized (hand-computed −₩6,164,384 / +₩3,657,534) |

## Known, deliberate divergence (calendar vs biz-ranked ramp)

For a TRIVIAL path (customPath exactly on the `target × day/simDays` line) the
engine's swap lanes ramp by BUSINESS-DAY RANK (`chart.py _ramp_factor_r`)
while bonds and this module use calendar semantics (`_factor` /
`buildTimePath`). Fixtures therefore use explicit non-trivial waypoint paths
(the engine's SIM2-4 activation rule then puts every lane on the same calendar
waypoint lerp). On a trivial default ramp the small weekend/holiday phase
difference lands in the 잔차 path — where a model gap belongs — and the FE
does not pretend to know the KR holiday calendar (position-bridge.ts
DATE-AUTHORITY note).
